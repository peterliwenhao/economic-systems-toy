# 共享接口草案

本页先固定后续研究设计必须回答的接口问题。字段和公式由 T-001 完成 v0.1 草案后，经团队评审再标为已决定。

## 环境接口

建议采用接近 Gymnasium 的最小接口：

```text
reset(seed, config) -> state, observations
step(actions) -> state, observations, metrics, terminated, info
```

必须明确：

- 全局状态与每类参与者可观察信息；
- 商品、货币、库存、生产与消费的记账顺序；
- 同步或异步行动顺序；
- 冲击的发生位置和随机数来源；
- 商品守恒、预算约束、库存非负与行动合法性不变量。

## 策略接口

规则、优化和 LLM 策略都实现同一抽象接口：

```text
Policy.act(observation, memory, budget) -> structured_action
```

所有行动进入环境前使用相同 schema 验证、边界修正、超时和失败处理。不能只为某一种机制提供更宽松的重试或额外信息。

## 机制边界

- 环境负责物理/会计状态转移和约束。
- 市场机制负责报价、撮合、价格与清算规则。
- 计划机制负责规定信息集下的分配决策。
- Policy 负责生成受约束行动，不定义制度规则。

## 评价接口

每个时间步至少保留：

- 状态和参与者观察；
- 原始策略输出与解析后的合法行动；
- 交易或分配结果；
- 约束检查；
- 指标增量；
- LLM 延迟、token、费用、重试与失败原因。
