## 交付内容

新建 `docs/research-design-v0.1.md`，至少包含：

1. **研究问题与边界**：具体比较什么，不比较什么，结果不能外推到哪里。
2. **环境形式化**：参与者、商品、状态、时间步、行动、观察、转移和不变量。
3. **机制定义**：市场和计划机制共享哪些条件，只在哪些配置规则上不同。
4. **信息公平性**：每类参与者能看到什么，通信和计算预算怎样记录与控制。
5. **策略与基线**：随机、规则、优化及 LLM 策略各自承担什么比较作用。
6. **指标草案**：公式或足够精确的定义、经济含义、主次关系和统计报告方式。
7. **验证案例**：至少一个可手算极小案例，以及一个应被系统拒绝或暴露问题的失败案例。
8. **待确认问题**：分别列出需要 LLM/计算建议和经济学建议的问题。

同时根据草案更新 `docs/project.md` 和 `docs/interfaces.md` 中对应的“待确认”内容，但不要把未经评审的选择写成最终决定。

## 验收条件

- [ ] 现有材料中的共识、分歧和待确认问题已归纳；
- [ ] 环境状态、参与者、商品、时间步、行动、信息集和约束可被另一位成员复述；
- [ ] 市场与计划机制的共同条件和差异清晰可审计；
- [ ] 信息、通信和计算预算的公平比较方法已经提出；
- [ ] 指标有定义及经济含义，不只是名称列表；
- [ ] 包含可手算案例与失败案例；
- [ ] 未把 toy 结果预设为对现实制度的判断；
- [ ] 待李文浩、刘充确认的问题被单独列出；
- [ ] 完成后写出简短交接摘要，说明完成内容、未决问题和建议下一步。

## 工作方式建议

可以使用自己的 Codex 帮助整理材料、检查结构和提出遗漏，但请亲自理解并能够解释每个状态变量、约束、机制和指标。遇到影响研究方向的选择时，保留备选方案与理由，不需要独自替团队作最终决定。
