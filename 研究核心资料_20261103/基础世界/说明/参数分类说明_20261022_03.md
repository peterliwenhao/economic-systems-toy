## 二、A类：当前需要遵守的结构与制度约束

### 共同世界

- 市场、兰格、Cockshott共享物理底座；制度差异放在覆盖项中。
- 一个agent对应一个家庭；实物为大米、小麦、铁。
- 当前结构为2个大米生产点、2个小麦生产点、2个铁矿。
- 无独立仓库；家庭储存有限，企业储存无限，企业生产能力仍有限。
- 家庭和企业均存在商品损耗，同种商品在两类持有者处采用相同腐坏率。
- 完整行动轮40小时；每自然日跨雇主劳动累计最多8小时；劳动任务不重叠。日界线映射尚未解决。
- 远程劳动不计通勤，但商品运输仍存在；运输采用每调拨指令、按距离扣固定绝对损耗的现有机制。
- 不劳动也有消耗；真实技能与主观认识分离，生产由真实物理条件结算。
- 家庭退出销毁家庭货币和实物，不销毁企业资产；退出者股份注销，剩余股东批量归一化。
- 旧库存迁移不能凭空删除或重复生成；库存账本记录生产、消费、运输损耗、腐坏和退出销毁等明确源汇。

### 制度覆盖项

- 市场米麦交易使用相同机制、共享时间窗，不固定米麦市场先后顺序；不能将此市场机制强加给计划模型。
- 市场家庭初始现金为0、企业初始资金平均分配；资金总额可校准。
- 工资合同必须预留资金；技能误判不追溯改价，不存在工人固定产量担保和自动自赔。
- 市场股东主动查询企业信息，而非自动推送。
- 当前计划覆盖项记录生产资产国有、短缺基本需求分配使用带种子的随机机制；Cockshott与包内“AI增强计划”的具体制度对应尚未明确。

上述“固定”表示在当前基准和测试中必须遵守，并非永远不可研究其他设定。若用户决定改变，需作为共同设定或制度版本变更记录。

## 四、C类：哪些目前确实交给AI设计

| 项目 | 授权/来源 | 当前设计及状态 |
|---|---|---|
| 家庭储存倍数n | 用户明确“n我希望你先给我设计一个” | 候选12；建议固定初始人均基本需求作为基准、米麦共享容量；后两项是AI建议，尚未确认 |
| 分商品腐坏率 | 用户要求先让AI给出 | 候选米2%、麦2%、铁0.1%/40小时；是抽象模拟起点，未声称现实测量依据 |
| 食品生产点ID分配 | AI主动提出，未单独获得定值确认 | G1/G4米、G2/G3麦；两组地块系数和均为2.0，只是避免一个维度总量失衡，不代表空间条件完全对称 |
| 食品生产技术与运输系数 | AI提出沿用旧值作为候选 | 不代表用户已经批准；需要结合米麦技能与需求检查 |
| 米麦消费/生产禀赋生成方式 | 用户要求AI设定并授权覆盖 | 已设米麦技能与偏好权重初值；替代与效用/健康聚合仍待明确 |

“交给AI设计”不等于模拟过程中每个agent可以选择腐坏率、储存容量、自己的真实技能或生产函数。这些应在初始化前生成并冻结，或按预先明确的规则演化。

## 五、D类：由模拟主体决定或环境结算的变量

本表区分原则适用于后续实现；尚未写入的具体决策权限应在对应制度模型确认，不能据此新增主体权限。

| 运行变量 | 决定者/来源 | 需要给定什么，不应写死什么 |
|---|---|---|
| 米麦购买、报价、出售、订单数量 | 有相应权限的家庭/企业 | 给预算、库存、信息和行动规则；不预设每轮必须买多少或某个价格 |
| 劳动供给、雇主选择、劳动安排 | 家庭及相应制度调度主体 | 给每日8小时和不重叠约束；不预设每户必须固定工作时长 |
| 招聘、工资报价、投入采购、生产安排 | 市场企业 | 给支付能力、技术和产能；实际签约工资、用工量由决策及合同产生 |
| 食品分配、计划产量、劳动调配 | 对应计划制度的决策机构 | 给同一物理约束和该制度信息权限；具体权限和算法由制度文件定义 |
| 实际米麦消费组合、储备目标 | 家庭或相应配给规则 | 先定义偏好及食品替代关系；不能用固定消费配比替代本应研究的选择 |
| 主观技能判断、预期、策略 | 主体基于可见历史形成 | 环境不能泄露真实技能；若采用公式学习则按明确公式执行 |
| 实际产量 | 环境物理生产引擎 | 由投入、劳动、技能、健康和产能计算；不是AI自由宣称的产量 |
| 实际库存、现金、健康、损耗、退出事件 | 环境账本和状态转移 | 给初始值与转移规则；后续数值按事件结算 |
| 成交价格、利润、就业、短缺、福利等指标 | 交易及生产分配结果 | 初始报价或价格边界可外生，运行结果不应预先锁定；计划价格另按制度规则确定 |

“自主选择”也受制度限制：例如市场工资谈判与兰格价格更新不应混为相同决策权限。

## 七、F类：必须先明确含义的未决规则

- 自然日如何嵌入40小时行动轮；跨轮工时如何累计。
- 原minimum_consumption的时间单位；闲时消耗是否另加、如何避免重复基础代谢。
- 消费禀赋已暂定为归一化偏好权重；米麦如何替代、如何将权重用于效用以及如何合成健康仍待明确。
- 容量是米麦合计还是分商品；平均消费基准固定还是动态；初始家庭集合还是存活家庭集合。
- 腐坏结算时点、新入库商品的计龄、在途是否计损；容量超额时的订单/交付处理。
- 旧粮拆米麦的规则、旧仓库接收主体及迁移运输损耗。
- 所有股东退出后的产权、控制权、资产和经营处置；退出时未完成合同的处理。
- 共享食品窗如何定义长度和行动预算、何时撮合、如何排程；不能只靠代码循环先处理米来隐式固定市场顺序。
- 米麦技术的地块系数、铁投入、分段函数和产能上限如何组合；旧表尚未形成完整无歧义公式。
- 兰格、Cockshott各自的决策权限、信息、分配和价格机制。

上述问题应先得到规则解释或方案授权，再把其中的数值转成可校准参数；不能用0替代null。

## 八、测试失败时，什么时候可以反过来改参数

| 发现的问题 | 正确处理 | 不应采用的做法 |
|---|---|---|
| 库存不平、现金负余额、工时超8小时、合同被事后改价 | 先修代码、测试口径或明确冲突规则 | 提高初始库存、资金或劳动上限掩盖错误 |
| 单元测试把旧14容量/单一谷物等已失效设定写死 | 按新版规则更新测试，验证公式与边界 | 为迎合旧测试撤销已确认新版设定 |
| 算法正确但生产和营养需求组合导致不可行 | 做资源和劳动可行性核算，再调整B类参数并记录理由 | 因某制度短缺就单独给它更高生产率 |
| 某主体选择导致经营失败或家庭退出 | 判断是否允许的内生结果，分析原因 | 把“所有主体永远生存”自动设成单元测试要求 |
| null导致无法初始化 | 完成F类定义，或使用明确标识的开发测试配置 | 自动补0或把AI建议写成用户定案 |
| 校准后对比结果改变 | 用同一新版共同参数重跑相关制度，报告版本、种子与敏感性 | 只重跑希望改善的一种制度或挑选种子 |

单元测试主要验证实现是否符合规则；资源可行性、长期生存和制度表现主要用校准、集成测试和模拟实验评估。数值可调，不意味着每个失败都应通过调参消除。

## 九、后续维护建议

YAML分类项已加入以下元信息（字段值通过JSON Pointer引用）：`category`、`set_by`、`status`、`unit`、`scope`、`fields`、`design_authority`、`constraints`、`depends_on`、`change_reason`。

比较三个制度前冻结共同参数配置并记录版本。调整后同步共同世界HTML、规则、YAML及所有依赖值；正式结果用更新后的同一配置重新比较。文件采用覆盖或另存，仍按用户当次选择执行；GitHub上传仍暂停。

当前主版本为第3版，2026-10-23覆盖更新米麦禀赋；未涉及的候选状态保持不变，旧版仅供回溯。
